# 패킷 프로토콜 (M1)

M1 단계의 연결 계층 규격입니다. M2에서 payload를 protobuf로 바꾸고 로그인·방 입장 패킷을 추가하며,
이 문서를 패킷 정의서로 확장합니다.

## 패킷 형식

TCP는 바이트 스트림이라 메시지 경계가 없으므로, 모든 패킷 앞에 고정 길이 헤더를 붙입니다.
수신 측은 헤더 4바이트를 먼저 정확히 읽고, 헤더가 알려 주는 길이만큼 payload를 읽습니다.

```
+-------------------+------------+--------------------+
| payloadSize (u16) | type (u16) | payload (N bytes)  |
+-------------------+------------+--------------------+
   little-endian       little-endian
```

| 필드 | 크기 | 설명 |
| --- | --- | --- |
| payloadSize | 2바이트 | 헤더를 제외한 payload 길이. 최대 4096 |
| type | 2바이트 | 패킷 종류 |
| payload | payloadSize 바이트 | 패킷 종류별 내용 (없으면 0바이트) |

- 모든 정수는 **리틀엔디안**으로 한 바이트씩 직렬화합니다. 구조체를 그대로 `send`하지 않아서
  컴파일러 패딩이나 엔디안 차이의 영향을 받지 않습니다.
- 한 번의 `recv`에 패킷이 일부만 오거나 여러 개가 붙어서 와도 위 규칙으로 올바르게 분리합니다
  (`tools/test_m1.py`의 fragmented / coalesced 테스트).

## 패킷 종류

| type | 이름 | 방향 | payload |
| --- | --- | --- | --- |
| 1 | Ping | 클라이언트 → 서버 | 임의 바이트 (Unity 클라이언트는 보낸 시각 8바이트를 넣음) |
| 2 | Pong | 서버 → 클라이언트 | Ping의 payload를 그대로 되돌림 |

## 연결 규칙

| 상황 | 서버 동작 |
| --- | --- |
| 아무 패킷도 없이 유휴 시간 경과 (기본 10초) | 연결 종료 |
| payloadSize > 4096 | 연결 종료 (메모리 소진 방지) |
| 알 수 없는 type | 연결 종료 (M1 한정. 이후 프로토콜 버전 정책에서 재검토) |
| 상대가 연결을 끊거나 읽기/쓰기 오류 | 세션 정리 후 제거 |
| 송신 큐에 1024개 이상 적체 (느린 클라이언트) | 연결 종료 |

하트비트: 클라이언트는 유휴 시간보다 짧은 간격(기본 3초)으로 Ping을 보내고, 서버가 Pong으로 답합니다.
서버는 어떤 패킷이든 받으면 유휴 타이머를 다시 시작합니다.

## 서버 실행 옵션

```
cppgameserver [port 1-65535] [idleTimeoutSeconds 1-3600]
```

기본값은 포트 7777, 유휴 타임아웃 10초입니다.
